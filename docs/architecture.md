# Архитектура

## Компоненты

```text
Браузер / Electron (EDITOR_URL)
        │ HTTPS
        ▼
Caddy / Nginx (на рабочем сервере)
        │ loopback
        ▼
Express
  ├── React-сборка dist/
  └── /api → авторизация / валидация → сервисы → Sequelize → MySQL
```

Docker не используется. MySQL установлен отдельно; Express запускается npm или systemd.
В разработке Vite отдаёт интерфейс и проксирует `/api` на Express.
Браузер обращается к API по относительному адресу своего origin, CORS не нужен.

## Сервер

- `server/src/app.ts`: HTTP-приложение, заголовки безопасности, origin, JSON, статика, ошибки.
- `server/src/index.ts`: подключение базы, запуск HTTP и graceful shutdown, очистка истёкших сессий.
- `server/src/routes/`: HTTP-контракты и валидация Zod.
- `server/src/middleware/auth.ts`: сессии, привязка к ожидаемому аккаунту, CSRF.
- `server/src/services/`: пароли, авторизация, конвертация DOCX.
- `server/src/repositories/documents.ts`: выборки и атомарные изменения документов.
- `server/src/models.ts`: модели Sequelize.
- `server/migrations/`: версионированная структура MySQL, учёт через Umzug / SequelizeMeta.
- `shared/api.ts`: типы ответов API без ORM-объектов и приватных полей.

## Хранение

- `users`: email и scrypt-хеш пароля с уникальной солью.
- `sessions`: хеш случайного токена, пользователь, CSRF-токен, фиксированный `expiresAt`.
- `documents`: владелец, имя, LONGTEXT, версия, `deletedAt`, даты создания / изменения.

Внешние ключи, InnoDB, utf8mb4, даты UTC. Папок и физических файлов документов нет.
`deletedAt IS NULL` означает «Все файлы», заполненная дата — корзину.
Имя не является идентификатором: одинаковые имена допустимы, документы различаются по ID.
Содержимое не возвращается в списках, страницы по 50 элементов.

## Сессии

Токен хранится только в cookie `editor_session`: HttpOnly, SameSite=Strict, Secure в production.
В базе хранится SHA-256 токена, а не сам токен. Сессия действует 24 часа от создания,
запросы не продлевают её. Logout отзывает текущую сессию.
Изменяющие запросы требуют точный Origin, пользовательский заголовок и для сессионных маршрутов CSRF-токен.
CSRF-токен и ID текущего аккаунта хранятся в памяти frontend, а не в localStorage.
Заголовок `X-Editor-User` предотвращает случайное смешивание аккаунтов при смене cookie в другом окне.
Права всегда проверяются по сессии, этот заголовок не является источником авторизации.

После истечения сессии редактор остаётся смонтированным, сеть сохранения приостанавливается,
появляется вход. Вход тем же аккаунтом сохраняет вкладки. Смена аккаунта с несохранёнными
данными требует подтверждения отказа от локальных правок.

## Состояние редактора и сохранение

`src/cloudWorkspace.ts` — отдельное состояние вкладок конкретного аккаунта.
`src/App.tsx` подписывается на него через useSyncExternalStore.
Вкладки держат текст, сохранённый снимок имени и текста, версию, курсор, режим и статус.
CodeMirror остаётся смонтированным для неактивных вкладок, сохраняя историю отмены.

Изменение → dirty → 800 мс → PATCH с версией → подтверждённый сохранённый снимок.
Очередь допускает один запрос сохранения документа одновременно.
Поздний ответ не помечает более новый текст сохранённым.
При неизвестном результате сетевого запроса сначала читается серверный документ:
подтверждённое сохранение распознаётся без повторной записи, чужая версия вызывает конфликт.
После сетевой ошибки автоматические повторы остановлены до ручного «Повторить» или повторного входа.

Сервер изменяет документ одной SQL-операцией с условиями `ownerId`, `id`, `version`, `deletedAt`.
Обновление текста, переименование, перенос в корзину и восстановление увеличивают версию.
Окончательное удаление разрешено только из корзины и тоже проверяет версию.
Устаревший запрос не может перезаписать текст или восстановить удалённый документ.

409 / исчезновение документа переводит вкладку в конфликт. Текст не заменяется автоматически:
можно создать копию или явно загрузить серверный вариант. При возвращении фокуса чистые
документы обновляются, а грязные проверяются на конфликт. WebSocket и realtime пока нет.
Закрытие вкладки не удаляет документ. Последняя закрытая вкладка оставляет пустую рабочую область.

## Импорт, экспорт, настройки

Импорт идёт multipart-запросом: файл до 5 MiB, итоговый UTF-8 текст до 2 MiB.
DOCX проверяется до конвертации: до 1000 ZIP-элементов и 20 MiB фактически распакованных данных.
DOCX → Mammoth → HTML → Turndown → Markdown, изображения отбрасываются.
DOC не поддерживается; бинарные и некорректные UTF-8 файлы отклоняются.
HTML создаётся клиентом из текущего текста через react-markdown + remark-gfm,
скачивание не зависит от сохранённого состояния и не меняет его.
Относительные ссылки не переписываются и ресурсы не копируются в облако.
Настройки интерфейса остаются в localStorage.

## Electron

Electron загружает только серверный `EDITOR_URL` (HTTPS, HTTP разрешён лишь на loopback).
Включены sandbox и contextIsolation, выключен nodeIntegration.
`shared/electron-api.ts` оставляет только меню, язык и индикатор несохранённых изменений.
Файловых IPC-методов больше нет. Проверяется origin и главный frame отправителя;
внешняя навигация, новые окна, webview и разрешения блокируются.

## Пока не реализовано

Папки, shared-доступ, realtime, история откатов, IndexedDB-черновики, восстановление открытых
вкладок после перезапуска, восстановление пароля, подтверждение email и установщики Electron.
Автосохранение не заменяет резервные копии. До подтверждения сервера не закрывайте окно.
