# Text Editor

Облачный текстовый редактор: React + CodeMirror 6, сервер Express + TypeScript,
MySQL + Sequelize. Один интерфейс работает в браузере и в Electron, который загружает его с сервера.

## Возможности

- Аккаунты с серверными сессиями на **24 часа с момента входа**, без автоматического продления.
- «Все файлы», отдельные открытые вкладки и корзина с восстановлением / окончательным удалением.
- Автосохранение после 800 мс без ввода и немедленное сохранение по Ctrl/Cmd+S.
- Атомарная проверка версии: устаревшее окно получает конфликт вместо перезаписи документа.
- При конфликте можно загрузить серверную версию или создать отдельную копию локального текста.
- Markdown: форматирование, GFM, предпросмотр, split view и синхронная прокрутка.
- Подсветка JS/JSX, TS/TSX, Python, HTML, CSS, JSON.
- Импорт UTF-8 и DOCX; скачивание текста и самостоятельного HTML.
- Русский / английский, темы, цвет акцента и настройки редактора.

Папок, общего доступа, совместного редактирования и истории откатов пока нет.
Версия документа защищает от конфликтов, но не является архивом предыдущих текстов.
Несохранённые правки остаются в памяти окна: офлайн-хранилище черновиков пока не реализовано.

## Локальный запуск без Docker

Нужны Node.js **22.16+**, npm и установленный MySQL **8+**.
Сначала создайте базу / пользователя и заполните `.env` — см. [подробную инструкцию](docs/development.md).

```bash
npm install
cp .env.example .env
# Отредактируйте DB_* в .env
npm run db:migrate
```

В двух терминалах:

```bash
npm run dev:server
```

```bash
npm run dev
```

Откройте **http://localhost:5173**. Для Electron в третьем терминале:

```bash
npm run build:electron
npm run electron
```

Для запуска собранного приложения сервером: `npm run build`, затем `npm start`.
При этом задайте `APP_ORIGIN=http://localhost:3000` и `EDITOR_URL=http://localhost:3000` в `.env`.
В production обязателен HTTPS.

## Проверки

```bash
npm run typecheck
npm run lint
npm test
npm run build
```

`npm test` не требует MySQL; интеграционный набор пропускается без `TEST_DB_NAME`.
Запуск тестов с реальной отдельной базой описан в руководстве разработчика.
